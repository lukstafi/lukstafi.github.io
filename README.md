# lukstafi.github.io

Personal website and blog. Visit [lukstafi.github.io](https://lukstafi.github.io).

## Building

Requires [Pandoc](https://pandoc.org/) 3.x.

```bash
# Build all HTML from Markdown sources
./scripts/build_all.sh

# Or build individually:
./scripts/build_notes_html.sh
./scripts/build_notes_html.sh notes/foo.md  # Build one note
./scripts/build_jca_html.sh
./scripts/build_agent_collab_html.sh
```

### Publishing a note to Substack

`scripts/publish_to_substack.py` converts a note in `notes/` to Substack's
ProseMirror draft JSON (via the pandoc custom writer `scripts/substack.lua`) and
creates a draft through the unofficial [`python-substack`](https://github.com/ma2za/python-substack) API.

Display equations use Substack's native `latex_block`. Inline math defaults to
Unicode generated by Pandoc's **texmath parser**, preserving nested scripts,
Greek letters, math alphabets, accents, and operator names. Scripts without
Unicode equivalents keep explicit grouping (`V^(π₁)`, `π_(θ)`). Stars and primes
use conventional `V*`, `Q*`, `s′`, and `π′`, without redundant script parentheses.
Expressions the
plain-text writer cannot represent become display equations with a warning;
they are never silently stripped or partially substituted.

Inline modes (`--inline-math`):

- `unicode` (default): readable text, including in email.
- `native` (experimental): `inline_latex` nodes with the original TeX. Substack
  [advertises inline math](https://substack.com/features), and an
  [editor extension author documents this node](https://geralynchong.substack.com/p/bse-2-building-in-line-latex-chrome).
  The private schema is not stable: check the **actual draft and email preview**
  before using this mode for publication. A local KaTeX preview alone does not
  establish editor/email compatibility.
- `raw`: literal `$...$` source.
- `block`: display equations, split out of surrounding paragraphs/headings.

Diagrams: Markdown images and Pandoc figures become captioned Substack images.
Local SVGs are rasterized to PNG at 2× resolution with an opaque background;
alt text and figure captions survive. PNG/JPEG/GIF/WebP images are supported too,
including base64 data URIs already embedded in some notes. Upload dimensions and
content type are retained for remote images.
Local paths resolve relative to the Markdown file, not the working directory.
Before draft creation, images upload through `python-substack` to Substack's
image service; repeated sources upload once. A missing file or failed upload
stops draft creation. Remote raster URLs are passed to that service; download
remote SVGs yourself and reference the local copy to rasterize them.

Tables: the [python-substack maintainers report no native table renderer](https://github.com/ma2za/python-substack/blob/main/docs/markdown.md).
The default `--tables list` retains the headers as labels on each row, allowing
prose to wrap on phones and in email. `--tables latex` emits a native equation
containing a LaTeX `array`, preserving cell math and escaping literal text. Use
it for **compact mathematical tables**; long prose tables become too wide in an
array. Images in cells survive list export; LaTeX mode rejects them explicitly
and recommends list mode. LaTeX `tabular` and arbitrary packages are not supported
by KaTeX.

Homebrew's Python is "externally managed", so install the dependencies into a
virtualenv:

```bash
python3 -m venv .venv-substack
.venv-substack/bin/pip install -r scripts/requirements-substack.txt

# Preview the generated JSON only (no credentials needed):
.venv-substack/bin/python scripts/publish_to_substack.py \
    notes/how-does-a-policy-improve.md --dry-run \
    --json-out .substack-export/policy.json \
    --preview .substack-export/policy.html

# Create a draft (reads credentials from .env / environment):
.venv-substack/bin/python scripts/publish_to_substack.py \
    notes/broadcast-aware-shape-inference.md
```

`--dry-run` does not authenticate or upload. Its JSON uses local `file:` image
URLs for inspection, so it is **not a ready-to-submit payload**. A normal draft
run writes `--json-out` after successful image uploads, with HTTPS URLs.
`--assets-dir` overrides the directory for generated PNGs. The HTML preview
renders the exported nodes (not the source Markdown); open it in a browser with
an internet connection to load its pinned KaTeX assets. It is a layout aid,
not a replica of Substack's editor or email renderer.

```bash
# Regression suite, including both October 4 RL essays:
.venv-substack/bin/python -m unittest discover -s scripts -p 'test_*.py'
```

CairoSVG may require the Cairo system library (`brew install cairo` on macOS).

Credentials go in a `.env` file at the repo root (git-ignored):

```
SUBSTACK_PUBLICATION_URL=https://yourpub.substack.com
# either e-mail/password, or a saved browser session (preferred, avoids captcha):
SUBSTACK_COOKIES_PATH=scripts/.substack-cookies.json
```

The title comes from the note's frontmatter; a leading `# H1` is dropped to
avoid duplicating it. A footer linking to the web version of the article is
appended automatically — the URL is derived from the note's path (e.g.
`notes/foo.md` → `https://lukstafi.github.io/notes/foo.html`); disable with
`--no-footer` or customise with `--site-url` / `--footer-prefix`. Run with
`--help` for all options.

### Blog essay length

Aim for 4,000–7,000 words per blog essay. The hard upper limit is 10,000 words;
an essay exceeding that limit must be split into multiple articles.

### Prompt companion pages

Each AI-authored article has a companion `notes/<base>.prompts.md` holding the
human-side prompts that steered it — the questions, framing, and
course-corrections — so the author's contribution is delineated from the
writing. These are stubs (`*Prompts not yet transcribed.*`) until filled in.

The links are injected automatically, never written into the article bodies:

- **HTML:** `build_notes_html.sh` appends a footer link from each article to its
  `<base>.prompts.html`, and a backlink from the prompts page to the article,
  whenever the companion `.prompts.md` exists.
- **Substack:** `publish_to_substack.py` appends a prompts-link footer beside the
  web-version backlink (disable with `--no-prompts-link`).
- **Home page:** `index.html` only carries a `prompts ↗` badge for the most
  recent article; the page doubles as a checklist of which stubs are filled in.

### Local preview

```bash
python3 -m http.server
# Then open http://localhost:8000
```

CSS paths are absolute (`/assets/...`), so a local HTTP server is required for previewing — opening HTML files directly via `file://` won't load the stylesheets.

## Design

The site uses [Tufte CSS](https://edwardtufte.github.io/tufte-css/) for typography and layout, with a custom dark mode implementation. Content pages are generated from Markdown via Pandoc using the [tufte-pandoc-css](https://github.com/jez/tufte-pandoc-css) template.
