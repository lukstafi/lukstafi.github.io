Two typings of one evaluation

Fix the runtime arguments of a call. Its inferred input predicate admits some keys \(k\). Write \(P(k,r)\) for \(\exists w.\,R(k,r,w)\), where \(r\) is the index of the number returned at runtime and \(w\) is private to the package. If the call admits both \(a\) and \(b\), every terminating evaluation gives a number satisfying \(P(a,r)\land P(b,r)\). The two openings can have different witnesses. For instance, write the interval as \(r=k+w\), \(0\le w\le n\). At the observed result \(r=s\), the lower key \(s-n\) needs \(w=n\) and the upper key \(s\) needs \(w=0\). When endpoints suffice

For a fixed proposed result \(r\), consider the set of keys \(k\) at which \(P(k,r)\) holds. Two endpoint typings recover the full intersection on every integer interval if and only if every such set contains all the integers between any two of its members. If the set has that property, membership at the endpoints entails membership at every interior key. Conversely, two members with a missing integer between them give an interval on which the endpoint test is inexact. The criterion applies after projecting the private witnesses. Over integer witnesses, even the single equation \(2w=k\) admits keys 0 and 2 while missing 1. Equivalence and parity counterexample

For translated intervals \([k+A,k+B]\), the bounds are monotone in \(k\). The smallest and largest admitted keys \(L,U\) determine the exact intersection \([U+A,L+B]\), even when some intervening keys are unavailable. Both endpoints must themselves be admitted. Attained-extrema theorem

A fixed package can require arbitrarily many typings

Let the runtime input be \(n\ge1\). The keys are \(1,\ldots,n\). At key \(k\), return any integer \(0\le r\le n\) except \(k\). The function actually returns zero in the base case. The recursive branch opens one call, tests \(1\le r\le n\), and returns zero on the surviving path. The public client merely observes a nonnegative number. Punctured-key program

For any package, a set of sampled keys excludes a guard exactly when it includes, for each result in the guard, a key whose package excludes that result. In this example the intersection over all keys is \(\{0\}\). Every positive \(j\le n\) is excluded by exactly one key, namely \(j\). Omitting that key leaves \(j\) in the sampled intersection. Hence exactly \(n\) result-independent typings are needed to rule out this guard using only the written packages. The source and the inductive strengthening \(r=0\) have constant size as the runtime input grows. For a fixed numeral \(n\), the same family also has a conjunctive presentation over integers with one private witness,

\[ \exists w.\quad 1\le r-k-(n+1)w\le n. \]

On the stated ranges choose \(w=0\) for \(r>k\) and \(w=-1\) for \(r<k\). At equality, no multiple of \(n+1\) is in \([1,n]\). With a binary-encoded coefficient this gives an exponential lower bound on the number of sampled keys in terms of formula length. The runnable source spells out the disequality using the two unit-separated inequalities. Sharp sample bound and conjunctive encoding
