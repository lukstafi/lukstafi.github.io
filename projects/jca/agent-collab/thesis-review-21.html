A demand that survives every induction jump

A binary postcondition \(\chi_K(\delta,\delta')\) relates the type of an existential result to the tuple of parameters carried by its package. In climb m t, the result has type \(\mathrm{Num}(r)\) and the parameter tuple carries \(m\). Write \(B_t\) for the band \(m\le r\le m+t\). When the stored relation is \(B_{20}\), projecting the base and recursive suppliers gives \(B_{19}\). The caller requires \(B_{20}\). Both bands satisfy the original clauses. Here is a recurrence test for this part of the table. Fix the input predicate and the package parameters. Let \(W(R)\) be the supplier summary after the jump and \(D\) the caller demand. Suppose abduction restores \(D\) whenever \(W(R)\) fails to entail it, every supplier justifies the restoration, and the remaining update state repeats. The relation stored by (4.6) is \(W(R)\land D\). If this is \(R\) again and some value satisfies \(W(R)\land\neg D\), induction gives the same relation and a fresh nonempty demand at every later pass. The stopping test observes that demand. Repetition of the stored predicate alone cannot establish convergence. The Lean lemma covers extensional predicate updates. Which part of a guarded branch can disappear?

Consider the constructor Pick : ∀i[i≤0]. Num i ⟶ Seed. A client matches Pick n when 1 <= n. Inside the arm it calls a recursive function f on Third Box, opens the returned pair and requires its first component to have type Cargo. The pattern gives \(n\le0\), so the client will never make this call. The previous implementation still tried to accommodate it at every positive outer budget. Original clauses and certificate

Write \(F\) for the other obligations, \(P\) for matching the pattern, \(E\) for checking the guard operands, \(G\) for the guard succeeding, and \(B\) for the body obligations. Suppose \(F\land P\land E\land G\) is impossible independently of \(B\). Then \[ F\land(P\Rightarrow E\land(G\Rightarrow B)) \quad\longleftrightarrow\quad F\land(P\Rightarrow E). \] The equivalence holds on each valuation. It therefore preserves every winning witness strategy under the original quantifier prefix, including strategies that share witnesses across guards. A contradiction that uses \(B\) itself would be circular. For example, the two bodies \(P\Rightarrow x\) and \(P\Rightarrow\neg x\) together force \(\neg P\). Deleting both admits \(P\). The machine representation matters

With native OCaml integers, \(n+1\le n\) holds at max_int. Overflow can also happen before the match. Feed min_int + 1 to fun n -> Pick (n+n) under the input refinement \(n\le0\). The mathematical sum is nonpositive, yet its machine value is 2. A later match on Pick n when 1 <= n must take the arm. With the float backend, converting the integer \(2^{53}+3\) yields the same float as \(2^{53}+4\), making a strict gap disappear even without addition in the source. All three examples execute the selected positive branch. Executable machine-boundary cases

The compiler enables this erasure for the native integer target when the compilation unit contains no source addition or scalar multiplication. Checking the whole unit covers a function that constructs a value later consumed by an earlier definition. A library caller generating annotations for multiple backends retains the bodies by default. As elsewhere in inference, external implementations are assumed to respect their declared types. The restriction leaves opportunities for a more precise analysis of where numeric values originate.

A constant-size solution that still fails at every positive budget

Put both calls behind 1 <= observed n. Each uses a fresh instance of f, opens the pair, and tests the first component against Box. The normalized guard-evaluation row requires \(i\le0\Rightarrow o=i\land h=o\land l=1\). Every client call, opening and payload-use row contains \(i\le0\land l\le h\). These premises are impossible whenever the guard-evaluation row holds. The definition and its suppliers have exactly the constant-size solution from the one-call example. Interpret the unary predicate as the instances of the displayed arrow type and the binary predicate as the pairs \((a,a)\) carried with parameter tuple \(\langle a\rangle\). Pick \(a=M\) for the initial instance. The third constructor supplies \(a\) directly, and each other constructor forces \(a=M\). Recursion preserves the parameter. Choosing \(o=h=i\) and \(l=1\) respects the guard’s witness dependencies. This verifies the original erased constraints. Writing the third-axis type explicitly while retaining both OCaml call sites still produces a type mismatch at the first-axis call. There is a structural obstacle to making both calls unconditional. Project a conjunctive free-type pattern to the four input axes and the first output component. Its ground leaves on these examples are fixed constructors or type holes. A domain admitting both marked inputs also admits the all-\(M\) input, by assigning \(M\) to the varying holes. On the all-\(M\), third-marked and first-marked inputs the actual outputs are \(M,C,C\), where \(C\) is Cargo. No fixed constructor has that column. No input axis has it either, since every axis is \(M\) on at least one of the two marked rows. Thus the output has an independent hole. Setting that hole to \(M\) preserves the third-marked input and admits a result its client rejects. This proves the obstruction even for a postcondition allowed to overapproximate the producer. Independent output hole lemma · Pattern classification

For this program, the original and strengthened searches together make 25 pass attempts. Ten pass-0 updates reach the budget comparison. Each leads to a type failure on pass 1. Five further attempts fail on pass 0. No proposal finishes, so the comparison before replaying a finished proposal is unreachable. The final use of the budget to extract an answer is unreachable as well. With the remaining settings fixed, every positive outer budget therefore gives the same finite quantifier violation. Budget zero stops at the first successful update. We compared the complete pass traces at budgets 1 and 10,000. This refutes successful convergence of the current search on size-bounded satisfiable constraints without claiming an infinite run of its repaired arithmetic jump.
