A countermodel for the consumer guard

Fix a proposed recursive scheme and an ordinary typing of the recursive call. Write \(B(x,r)\) for the facts from that typing, where \(x\) includes its input coordinates and \(r\) is the shared result. A candidate expression gives key \(q_i(x,r)\). Write \(A_i\) for the admission conditions at this key and \(P_i(x,r,w_i)\) for the package facts with fresh private witnesses \(w_i\). The compiler can certify exclusion of a guard \(G\) by checking that the following formula has no model,

\[B(x,r)\land G(x,r)\land \bigwedge_i\bigl(\neg A_i(x,r)\lor\exists w_i.\ P_i(x,r,w_i)\bigr).\]

Every actual return that reaches the guard would be a model. Where the function admits a key, its typing supplies the required witnesses. The argument permits a different set of admitted keys at every observation. With exact arithmetic and exact admission predicates the test captures everything this finite family can rule out. The compiler can use sufficient admission conditions such as an explicit witness for a hidden coordinate. These give it fewer typings than the exact predicate might admit. The admission check itself uses rational arithmetic. To seek a countermodel it tries a postcondition or the failure of one admission atom. Failing \(a\le b\) requires \(a>b\). Two keys that work only together

For \(n\ge2\), let flag zero admit \([0,n]\) and flag one admit \([-n,0]\). The primary key 0 works in both. The package permits \(0\le r\le1\) and forbids the keys \(n+1-r\) and \(-n-1+r\). At zero both holes are outside either domain. At one the holes are \(n\) and \(-n\). The step must rule out this latter result under both flags. Program

Even inside the guard, a procedure that licenses each probe uniformly can miss both proofs. At \(r=1\) each finite expression built from integer-affine terms, addition, negation, minimum and maximum changes by at most some \(C\) when the flag changes from zero to one at fixed \(n\). An affine leaf changes by its flag coefficient. Addition adds the bounds and min or max takes the larger bound. Choose \(n\) greater than the bound for every expression in the proposed pool. If an expression is admitted in both states, it is nonnegative at flag zero and nonpositive at flag one. Its two values stay within \(C\) of zero. Neither can reach the refuting endpoint. How many conditional keys can be necessary?

There is a sharp bound for a family with \(m\) input modes numbered \(1\) through \(m\). At mode \(j\) admit just keys 0 and \(jn\), and at a hypothetical return of one let only \(jn\) refute it. The domain is the union of \(m\) linear cases, one for each fixed mode number. For example, take results zero and one and forbid the keys \(in+1-r\) for each mode number \(i\). At zero none of these holes equals an admitted key when \(n\ge2\). The \(m\) expressions \(n,2n,\ldots,mn\) suffice. Each gets used only where it is admitted.

A finite pool of fewer than \(m\) affine min/max expressions fails at some width. Fix the guard \(r=1\), the initial key 0 and any two distinct modes \(i,j\). For one such expression the difference between its values at these modes is bounded independently of \(n\). Take a common bound for all expressions in the pool and all pairs of modes. Choose a larger \(n\). Hitting \(in\) at mode \(i\) and \(jn\) at mode \(j\) would require a change of at least \(n\). Each expression can therefore cover at most one mode at that width. This lower bound allows conditional admission and arbitrarily large coefficients in the proposed expressions. The only result fact the consumer needs is still \(r=0\).
