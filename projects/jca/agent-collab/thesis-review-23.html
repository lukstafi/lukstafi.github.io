When independent inference is enough

Fix the input predicates, the parameter tuple of each result, and any legal first-order witness choices shared with the clients. Suppose the remaining producer clauses have the form \(R_1(a_1)\land\cdots\land R_n(a_n)\Rightarrow R(b)\) after instantiation. Keep the ground instances whose first-order premises hold. A base result has \(n=0\). Several mutually recursive postconditions fit these rules by tagging a tuple with its predicate name.

Let \(L\) contain exactly the conclusions with finite derivation trees. Attaching the finitely many premise trees beneath a rule instance puts its conclusion in \(L\), so \(L\) satisfies every rule. Conversely, induction on a tree shows that every producer solution contains its conclusion. Thus \(L\) is the least producer solution. Suppose also that shrinking these relations preserves the remaining client obligations, as it does for openings used only as hypotheses. Then some producer solution satisfies the clients if and only if \(L\) does. The implication from an arbitrary solution keeps the same choices at the shared interface. To infer a written scheme from the reverse implication, \(L\) itself must be expressible, or one must find an expressible closed enlargement which still satisfies the clients. Two choices of package parameter

Give the helper two arguments of indices \(i\) and \(-i\) and let it return the first. Either index is available to carry as the parameter \(k\). Write \(X(i,k)\) for the available package at a call and \(R(k,o)\) for its payload. The obligations below admit the call at every \(i\), require the producer to supply its actual output, and let the client demand that output back. \[ \forall i.\,\exists k.\,X(i,k),\qquad X(i,k)\Rightarrow R(k,i),\qquad X(i,k)\land R(k,o)\Rightarrow o=i. \]

One solution uses \(k=i\) and \(o=k\). The other uses \(k=-i\) and \(o=-k\). No feasible result relation is contained in both, even if its call predicate can be chosen freely. At \(i=1\) there must be a \(k\) such that \(R(k,1)\). Containment would give both \(k=1\) and \(k=-1\). Yet in each solution the relation visible after opening, \(\exists k.\,X(i,k)\land R(k,o)\), is exactly \(o=i\). Intersecting private postconditions before aligning their coordinates destroys a real call. Jointly checking the chosen call predicate and result relation preserves it. A supplier with an unfixed existential output choice can likewise lack a least relation even over two Boolean values. No-common-result and observation proofs

Which inputs may share one parameter?

Suppose the available supplier outputs at input \(i\) form a set \(S_i\) and the client allows a set \(A_i\). Propose a parameter \(k=c(i)\). A relation satisfying \(S_i\subseteq R(c(i))\subseteq A_i\) for every \(i\) exists exactly when \[ c(i)=c(j)\quad\Longrightarrow\quad S_i\subseteq A_j \] for every ordered pair of inputs. Necessity follows by opening the same package parameter at \(j\). For sufficiency take \(R(k)\) to be the union of the supplier sets over all \(i\) with \(c(i)=k\). When clients demand the exact output \(f(i)\), the test says that \(f\) must be constant on each set of inputs sharing a parameter. Either signed coordinate passes for the opposed-index helper. A constant parameter would merge 1 and \(-1\) and fail. Parameter compatibility and exact-output proofs

In a recursive definition, changing the parameter can change the supplier sets themselves. Consider two input states. The first supplies 0. The second supplies 1 and has the additional rule that a recursive result of 0 supplies 2. With separate parameters the second rule never fires, and both clients can require an output at most 1. Merging the parameters makes 0 available to the second rule. It now supplies 2, which violates the client. Comparing the old outputs on the merged inputs would pass the displayed test. Applying the producer rules on the proposed interface before checking the clients detects the failure. Finite counterexample
